# 강의실 지킴이 · 사용 현황과 모델 관리

첫 화면에서 경비원이 여러 강의실의 **모델이 추정한 사용 상태**를 확인하는 서비스입니다. 현재는 시연 명칭의 101~103호·201~203호 6개와 가상 센서 데이터를 사용하며, 실제 센서 수신 API도 제공합니다. 기존 학습·평가·버전·단건 예측 기능은 **모델 관리** 영역에 보존합니다. FastAPI는 Swagger UI를 제공하고 React 화면은 **Vite 개발 서버**를 사용합니다. 로그인·권한 제어는 구현하지 않았습니다.

## 실행

Docker Desktop의 Linux 컨테이너 엔진과 Docker Compose 2.24 이상이 필요합니다. Python·Node·가상환경을 별도로 설치하지 않습니다. 저장소 루트의 CMD에서 실행합니다.

```cmd
docker compose up -d --build
```

- [웹사이트](http://localhost:5173/): 강의실 현황 / 모델 관리(대시보드·센서 실험·모델 학습).
- [Swagger UI](http://localhost:8000/docs): API 입력 규격과 실제 요청.

이미지 빌드에서는 모델 학습·평가·테스트를 실행하지 않습니다. 런타임에는 기본 모델 준비 → API 준비 → Vite 실행 순서이며 trainer의 `Exited (0)`은 정상입니다. 저장된 기본 모델이 있으면 그대로 사용하고, 기본 모델이 없는 초기 런타임에만 trainer가 학습합니다. 처음 이미지와 패키지를 받을 때 인터넷이 필요합니다.

```cmd
docker compose ps -a
docker compose logs --tail 50 trainer api web
```

Compose는 루트 `.env`를 자동으로 적용하고, 없으면 `.env.example` 기본값을 사용합니다. 포트 변경은 사용자가 직접 `.env`의 `API_PORT` / `WEB_PORT`를 수정합니다. 처음 생성할 때만 아래 명령을 사용합니다.

```cmd
copy .env.example .env
```

`.env`는 Git에서 제외하며 애플리케이션 코드에서 직접 읽지 않습니다. 웹의 `/api` 요청은 내부 API로 프록시하므로 API의 호스트 포트를 바꿔도 프런트 수정이 필요 없습니다. 호스트 포트는 `127.0.0.1`에 연결됩니다.

## 경비원용 강의실 현황

전체·불 확인 필요·사용 중 예상·비어 있음 예상·연결 및 측정 확인 수를 표시합니다. 불 확인 대상부터 정렬하며 이름·층·상태로 필터링할 수 있습니다. 사용 여부 예상과 불 확인 대상은 중복될 수 있습니다. 상세에는 확인 이유·지속 시간·마지막 갱신과 밝기·이산화탄소·습도 변화가 나오고, 모델 확률·버전·시간표·측정 ID는 접힌 기록 영역에 보존합니다. 사용 여부 예상은 예약·출입 가능 여부가 아닙니다. 모델 관리의 데이터 조회 실패나 과거 버전의 입력범위 복원 실패가 강의실 현황을 막지 않습니다.

### 불 확인 참고 신호

**밝기 300 lux 이상·CO₂ 650 ppm 이하가 유효 측정에서 10분 이상 지속**되면 별도 `light_check.requires_check=true`로 반환합니다. 모델의 사용 여부 예상을 변경하지 않으며, 모델이 사용 중으로 예상해도 확인 신호가 함께 표시될 수 있습니다. 습도는 참고값으로만 표시하고 조건에는 쓰지 않습니다. 햇빛·환기 영향이 있으므로 사람 없음이나 조명 켜짐을 확정하지 않고 자동 소등도 하지 않습니다.

이는 시설에서 검증한 기준이 아닌 **시연용 가정**입니다. 기존 통합 학습 CSV의 밝기는 0~2,170 lux, CO₂는 380~2,028.5 ppm이며, 이 범위와 시연 흐름을 참고해 초기값을 정했을 뿐 모델 학습·정확도 평가로 튜닝하지 않았습니다. 실제 시설에서는 센서 위치·햇빛·환기를 고려한 기준 교정이 필요합니다. 아래 환경변수로 기준을 설정하며 모두 유한한 양수여야 합니다.

| 환경변수 | 기본값 | 의미 |
|---|---|---|
| `LIGHT_CHECK_MIN_LUX` | 300 | 밝기 하한, lux |
| `LIGHT_CHECK_MAX_CO2_PPM` | 650 | CO₂ 상한, ppm |
| `LIGHT_CHECK_HOLD_SECONDS` | 600 | 지속 시간, 초 |
| `LIGHT_CHECK_MAX_GAP_SECONDS` | 120 | 연속으로 인정하는 측정 시각 간 최대 공백, 초 |

개발 Compose와 EC2 운영 Compose 모두 이 기준을 API에 전달합니다. 운영 시에는 배포 명령에서 지정한 환경 파일의 값으로 조정하며, 생략하면 위 기본값을 사용합니다.

지속 시간은 조회 횟수나 폴링 시간이 아니라 **새롭게 최신 반영된 측정의 시각 차이**로만 누적합니다. 실제 센서는 실제 측정 시각, 시연은 가상 측정 시각을 씁니다. 측정 간 공백이 `LIGHT_CHECK_MAX_GAP_SECONDS`(기본 120초)를 초과하거나 실제 수신 간격이 `SENSOR_STALE_SECONDS`(기본 60초)를 초과하면 연속 조건을 새로 시작합니다. 과거·동일 시각·중복 측정은 누적하지 않습니다. 실센서 측정이 수신 시각보다 `SENSOR_STALE_SECONDS` 초과 오래됐거나 5초 초과 미래이면 참고 신호에서 제외하며, 조회 시에도 오래된 측정의 신호를 현재 상태로 표시하지 않습니다.

소스 전환·시연 처음부터·API 재시작·기준 변경 뒤에는 새 연속 측정을 확인합니다. 시연 정지 중에는 지속 시간이 늘지 않고 확인 대상 집계에서도 제외하며 마지막 참고 정보로 표시합니다. 연결 이상을 우선 표시하고 사용 여부 예상 자체는 마지막 기록에 보존합니다. 신호 상태·관찰 시작·기준이 바뀔 때만 기존 실행별 `model.jsonl`에 `event_type=patrol`로 센서 근거와 기준을 기록하며 조회는 이벤트를 만들지 않습니다. 이 규칙 결과를 실제 정답이나 학습 라벨로 저장하지 않습니다.

서버는 **UTC 05:00~24:00** 하루 시연 시계를 공유합니다. 기본 속도는 실제 1초당 시연 5분이며 하루 약 228초입니다. 24:00 도달 시 마지막 측정 시각은 다음 날 00:00(UTC)입니다. 재생·일시정지·1/5/10/20분 속도·처음부터 제어는 모든 브라우저에 함께 반영됩니다. 페이지나 탭마다 생성기를 만들지 않습니다. 시연이 끝나면 정지하며 처음부터로 새 세션을 시작합니다. API는 하나의 worker로 실행하며, SQLite 서비스 잠금으로 중복 생성기를 방지합니다.

강의실마다 다른 가상 시간표가 밝기와 CO₂ 축적·감소, 온습도 변화에 영향을 줍니다. 새 시연(v2)의 103호는 **12:00 수업 뒤에도 밝기가 남고 CO₂는 점차 낮아지는 예시**를 포함합니다. 1·5·10·20배속 모두 분 단위 측정을 빠짐없이 생성하므로 같은 가상 시각에는 같은 참고 신호가 나옵니다. 기존 v1 시연 위치는 보존하며 **‘처음부터’를 누르면 v2 예시**를 시작합니다. 센서 궤적은 재현 가능하지만 현실에서 검증한 생성 모델은 아닙니다. **사용 여부 예상은 저장 모델의 실제 예측이고, 불 확인 신호는 센서 규칙**입니다. 둘 다 시간표나 시나리오의 내부 정답을 화면 판정에 직접 사용하지 않으며 재학습 CSV에 자동 추가하지 않습니다.

기본 모델은 `models/weights/current.json`이 가리키며 현재 v7(Temperature·Humidity·Light·CO2·Hour, 요일 미사용)입니다. 측정마다 기본 모델을 다시 확인하므로 기본 모델을 바꾸면 다음 측정부터 반영되고, 이전 예상 상태 기록은 당시 모델 버전을 그대로 보존합니다. 시나리오와 예상 상태가 다를 수 있으며 이를 정확도로 표시하지 않습니다.

수신 없음은 **수신 대기**, 추론 실패는 **판별 불가**, 실제 서버 수신 이후 기본 60초 초과는 **확인 필요**입니다. `SENSOR_STALE_SECONDS`로 지연 기준을 바꿀 수 있습니다. 가상 미래 측정 시각을 신선도 판단에 사용하지 않습니다. 시연 정지·종료 시 마지막 판별을 보존하고 정지 원인을 표시하며 60초가 지나면 지연 상태로 전환합니다. 화면은 1초 간격으로 다시 조회하고 통신 장애 시 마지막 값을 현재 상태인 것처럼 표시하지 않습니다.

### 센서 수신과 시간 계약

`GET /classrooms`는 저장된 최신 상태·공유 시계를, `GET /classrooms/{id}`는 최신 관측·짧은 이력을 반환합니다. 조회 자체는 새 추론을 실행하지 않습니다. `POST /classrooms/{id}/measurements`는 아래와 같이 필수 센서 4종을 받습니다. 누락값은 기본값으로 채우지 않습니다.

```json
{
  "measurement_id": "sensor-101-20261028-0001",
  "observed_at": "2026-10-28T09:00:00+09:00",
  "source": "real",
  "Temperature": 22.0,
  "Humidity": 28.0,
  "Light": 450.0,
  "CO2": 800.0
}
```

`observed_at`은 UTC offset 또는 `Z`가 필수입니다. 원본 시각과 센서값을 보존하며 **전달된 offset 기준의 센서 현지 시각에서 Hour·DayOfWeek를 파생**합니다. 예: `2026-10-28T23:00:00+09:00`은 Hour 23입니다. 중복·늦은 측정 판정은 UTC로 정규화한 시각으로 비교합니다. 기존 저장 모델은 전달받은 Hour·DayOfWeek를 그대로 사용하며 서버가 새 학습 규칙에 맞춰 자동 변환하지 않습니다. 화면의 측정·시연 시각은 UTC, 실제 수신 시각은 KST로 명시합니다. `received_at`은 서버의 실제 UTC 수신 시각입니다.

새 학습의 시간 정책은 **`source-local-time-v1`**입니다. 통합 CSV의 Room_A/Room_B는 UTC에서 `Europe/Vienna`로 변환해 DST를 반영한 Hour·DayOfWeek를 만들고, legacy는 시간대 미확인이므로 원래 시각을 유지합니다. 합성 CSV는 명시된 offset의 현지 시각을 사용합니다. 피처를 바꾸어도 Graz 및 offset이 있는 자료의 **분할·중복 검사 축은 UTC naive**이며, 시간대가 없는 legacy 축은 원래 naive 시각입니다. CSV 원본과 출처 파일은 수정하지 않습니다.

정책은 데이터 요약·학습 계획·새 체크포인트·학습 보고서·생성 출처·추론 로그의 `time_feature_policy`에 기록합니다. 정책이 없는 기존 가중치의 변환·지문은 유지하며 로그에는 `unrecorded-legacy`로 표시합니다. 기존 모델에 새 정책을 소급 부여하지 않습니다. HTTP 센서 실험에서는 해당 모델의 학습 당시 시간 기준에 맞는 Hour·DayOfWeek를 직접 전달해야 합니다.

유효한 실센서 측정이 들어오면 해당 방만 실센서 모드가 되어 시연이 덮어쓰지 않습니다. 동일 방·source·measurement_id의 같은 내용은 중복으로 반환하고 다시 추론·반영하지 않습니다. 같은 ID에 다른 내용이면 HTTP 409입니다. 과거·동일 시각의 늦은 측정은 기록하되 최신 상태를 덮어쓰지 않습니다. 응답에는 measurement_id·inference_id·중복 여부·최신 반영 여부가 있어 후속 실제 정답과 연결할 수 있습니다.

`PUT /classrooms/{id}/source`에 `{"source":"simulation"}` 또는 `{"source":"real"}`을 보내 소스를 명시적으로 전환합니다. 전환 직후에는 수신 대기이며 새 측정부터 반영합니다. 상세 화면에서도 전환할 수 있습니다. `POST /simulation/control`은 `action=play/pause/restart/speed`와 필요 시 `speed=1/5/10/20`을 받습니다. 시연에는 scenario/session ID를 보존하고 로그의 `source=simulation/real/experiment`로 시연·센서 수신·모델 관리용 단건 실험을 구분합니다.

상태는 `CLASSROOM_STATE_DIR`(컨테이너 기본 `/app/state`)의 SQLite에 저장합니다. Compose의 `./state:/app/state`는 쓰기 가능하고 Git에서 제외합니다. 각 방의 최신 관측·판별과 최근 96건 본문을 보존하며 중복 측정 ID 원장은 별도로 디스크에 남깁니다. 메모리에 무제한 이력을 누적하지 않습니다. 재기동은 공유 시연 위치·재생 상태·실센서 모드를 복원합니다. 시연은 종료 중 지난 실제 시간을 가상 시각에 더하지 않습니다. 저장소가 준비되지 않으면 현황 API는 사유와 HTTP 503을 반환하고 모델 관리를 계속 제공합니다.

## 모델 관리에서 학습

1. **모델 관리 → 모델 학습** 탭에서 실험 이름을 정합니다.
2. 기온·습도·조도·CO₂·시간·요일의 스위치를 켜거나 꺼 **실제 학습 피처**를 선택합니다. 최소 한 개가 필요합니다.
3. 학습률·에포크·배치·신경망 구조 등을 조정하고 **학습 시작**을 누릅니다.
4. 진행률·학습 손실·검증 손실을 확인합니다. 학습은 별도 프로세스에서 실행하므로 탭 이동과 페이지 새로고침 후에도 계속됩니다.
5. 완료하면 새 `vN`의 가중치와 보고서가 저장됩니다. 대시보드에서 버전을 선택해 설정·정확도·정밀도·재현율·F1·혼동 행렬·학습 곡선을 확인합니다.
6. **설정 불러오기**로 기존 실험을 수정해 다시 학습하거나, **예측 실험**으로 해당 가중치를 테스트합니다. 보고서는 JSON으로 내려받을 수 있습니다.

피처 카드의 센서 슬라이더는 **저장된 모델의 예측 미리보기 입력**입니다. CSV의 모든 행을 동일한 센서값으로 바꾸거나 학습 데이터를 조작하지 않습니다. 하이퍼파라미터 슬라이더는 실제 학습 설정에 적용됩니다. 처음 학습하지 않은 초안 설정으로 예측하는 것처럼 표시하지 않습니다.

조도와 다른 피처를 함께 선택하고 **조도 제외 모델도 비교 학습**을 켜면, 동일한 데이터와 설정으로 조도만 뺀 모델도 학습합니다. 같은 버전 안에 두 가중치를 저장합니다. 조도를 끄거나 조도만 선택하거나 비교 옵션을 끄면 선택한 피처의 모델 하나를 저장합니다. 조도 제외는 `Light=0`을 입력하는 방식이 아닙니다.

동시에 한 학습을 실행합니다. 진행 중 추가 요청은 HTTP 409입니다. **학습 중지**는 다음 배치에서 반영하며, 실패·중지 이력을 남기고 완성되지 않은 모델은 등록하지 않습니다. 저장이 완료된 직후의 중지 요청은 이미 완료된 모델을 취소하지 않습니다. 서버 프로세스가 중단된 작업은 재조회 때 실패 상태로 정리하여 다음 학습을 막지 않습니다.

### 생성 데이터를 학습에 보충하기

기본값은 기존 실제 CSV만 사용하는 학습입니다. 독립 생성기로 `data/simulated/<생성ID>/`를 만든 뒤 **모델 관리 → 모델 학습 → 학습 데이터 구성**에서 해당 생성 ID를 선택합니다. 새 생성물이 보이지 않으면 **데이터 다시 확인**을 누릅니다. 생성물은 Git·이미지에 포함되지 않으므로 사용하는 환경에서 직접 준비해야 합니다.

**합성 추가량의 분모는 실제 fit 행수**입니다. 기본 25%는 실제 fit 100행당 합성 최대 25행을 추가한다는 뜻이며, 전체 fit에서 합성 비중은 최대 20%입니다. 설정 상한은 실제 fit의 100%이고, train/train_only 후보가 부족하면 가능한 만큼만 선택합니다. 화면에 요청 비율과 실제 선택 행수·비율을 표시하며, 행 선택에는 학습 설정의 랜덤 seed를 사용합니다. 생성물의 validation/test 방은 학습에 넣지 않습니다.

합성 보충 시 실제 자료를 먼저 나눕니다. Graz 두 방은 공통 날짜 경계를 사용하고 경계 앞 1시간의 fit 행을 제외하며, 기존 자료도 날짜 단위 경계와 같은 간격을 적용합니다. 실제 검증 자료로 가중치를 선택하고 `test_dataset.csv`는 변경 없이 최종 평가에 사용합니다. 날짜 그룹과 간격 때문에 실제 검증 행 비율은 요청 비율과 다를 수 있으며 화면에 적용 행수와 경계 제외 행수를 표시합니다. **합성을 끈 비교 실험에도 ‘Graz 두 방 공통 시간 분할’을 켜고 같은 검증 비율을 사용**해야 합니다. 기본 출처별 분할에서 두 방의 동시각 중첩이 있으면 별도 경고합니다.

기본 `canonical` 모드와 기존 산출물은 **canonical training 전체로 보정되어 실제 validation의 통계도 포함**합니다. 공통 시간 분할만으로 이 보정 경로의 누수가 해소되지는 않으므로 해당 생성물을 보충한 검증 성능을 독립 검증으로 해석하면 안 됩니다. 새 파이프라인은 실제 fit만으로 다시 보정하는 `fit_only` 경로를 제공하고 실제 분할 행 해시의 일치를 확인합니다. 성능 향상은 보장하지 않으며 같은 평가 자료로 반복 조정한 성능도 독립적인 최종 검증은 아닙니다.

`INCOMPLETE`, 품질 실패, 해시 불일치, 행 연결·가상 인원 정답 불일치, 허용 경로 밖 파일은 후보에서 제외하고 이유를 표시합니다. 확인한 데이터플랜과 제출 시 구성이 달라지면 다시 확인하도록 거부하며 작업 실행 시에도 재검사합니다. 작업 이력·실행 로그·버전별 보고서에는 실제·합성 행수, 선택 비율·seed, 생성 ID, manifest/프로필/CSV 해시, 방별 파티션·보정 출처, 실제 검증·평가 정체성을 기록합니다.

**기존 예측 로그는 학습에 넣지 않습니다.** `label_source=model_prediction`은 모델 출력이며 실제 정답이 아닙니다. 과거 시연 로그를 생성 CSV와 시각·측정 ID만으로 연결하지 않고, 입력·예측·버전 분석용으로 보존합니다. 실제 정답이 확실히 연결된 로그 입력 경로는 현재 제공하지 않습니다.

### 가상 현장 개선 파이프라인

모델 관리의 **현장 개선 파이프라인**은 생성기를 시연 현장의 관측·정답 공급원으로 사용합니다. 경비원 화면의 공유 시연이나 실제 센서 상태와 별개이며, 화면 진입만으로 예측·학습을 시작하지 않습니다.

학습 방식은 **독립 가상 정답을 사용하는 지도학습 재학습**입니다. 기존 PyTorch 분류기의 `BCEWithLogitsLoss`를 사용하며 행동·보상·정책 갱신이 없는 현재 구성은 강화학습(RL)이 아닙니다. 정답 없는 과거 일반 추론 로그나 모델의 예측값을 정답으로 바꿔 학습하지 않습니다.

1. **fit-only 현장 데이터 생성**: 생성 요청은 HTTP 202와 작업 ID를 즉시 반환하며 화면은 작업 상태를 조회합니다. 페이지를 나가도 접수한 생성은 계속되고, 작업 목록에서 다시 확인할 수 있습니다. 같은 설정의 진행 중 요청은 하나로 합치며 완료 산출물은 해시 검증 후 재사용합니다. 중단된 작업은 같은 설정으로 재시도하면 미완료 폴더를 `.incomplete` 아래 보존하고 새로 생성합니다. 손상된 완료 산출물은 덮어쓰지 않으며 새 seed가 필요합니다. 실제 fit/validation은 공통 날짜 경계·1시간 간격으로 먼저 확정하고 보정은 fit만 사용합니다. 분할 행 해시·비율을 profile/manifest에 기록하며 실제 test는 읽지 않습니다. 기본은 3개 방·7일, 생성물의 방별 train/validation/test 파티션은 유지합니다.
2. **관측 묶음 고정 → 예측 시작**: 생성 ID·seed·행수·기준 모델을 선택합니다. 관측 해시와 모델 파일 해시를 고정하고, offset 현지 시각의 센서·시간 피처만 모델에 전달합니다. 기본 모델을 나중에 바꿔도 실행 모델은 바뀌지 않습니다. 모델 파일이나 생성물 해시가 바뀌면 중단합니다. 중지·재개·재조회는 동일 관측과 inference ID를 재사용합니다.
3. **정답 연결·오판 분석**: 생성 ID/방/row_id로만 가상 인원수 정답을 연결합니다. 정답 0과 무정답은 구분하며 실제 모델 예측은 별도 필드에 보존합니다. 전체·주말·야간·7종 사건·방·파티션별 혼동행렬과 지표, 최대 50개 오판 근거를 확인합니다. 빈 그룹·분모가 없는 지표는 평가 불가로 표시합니다. 모두 시뮬레이션 지표입니다.
4. **학습용 정답 관측 데이터셋 확정 → 재학습 설정으로 가져오기**: 완료된 fit-only 실행의 train/train_only 관측만 사용합니다. 최소 절반은 일반 무작위 표본, 나머지는 오판 우선 보충이며 중복 없이 확정합니다. 최종 예산 축소·CSV 중복 제거 후에도 같은 정책으로 다시 선택합니다. 일반 표본이 부족하면 오판만 채우지 않고 보충량을 줄이며, 예산이 1행이면 일반 표본만 사용합니다. 생성 행 키·원본 해시·정답 출처·표본 정책·기준 모델 해시를 데이터셋 ID로 버전화합니다. CSV+정답 관측 총량은 실제 fit의 100% 이하이며 실제 일반/오판 보충량과 중복 제외량은 데이터플랜에 기록합니다. 학습 화면의 **학습 시작**은 사용자가 별도로 눌러야 합니다.
5. **동일 관측 비교 준비 → 후보 예측 / 비교 진행**: 기준 실행의 고정 validation/test 관측만 후보 모델에 전달합니다. 기준·후보가 모두 예측한 동일 행만 비교하며 미완료 여부와 상황별 오류 증가도 표시합니다. 이는 반복 개선용 시나리오 검증이며 최종 실제 `test_dataset.csv`와 다릅니다. 최종 실제 test로 오판 행을 채집하거나 자동 후보 선택을 하지 않습니다. 모델 채택은 기존의 수동 기본 모델 선택을 사용합니다.

CLI 생성물은 기존 `data/simulated`에서 읽습니다. 웹 생성물과 실행·확정 데이터셋 상태는 쓰기 가능한 `CLASSROOM_STATE_DIR`(기본 `state`) 아래 `simulated/`와 `pipeline.sqlite3`에 저장합니다. 기존 Compose의 읽기 전용 `data` 마운트를 변경하지 않아도 사용할 수 있습니다. 웹 생성물은 Git·이미지에 넣지 않습니다. 기존 canonical 전체 보정 산출물은 보존하고 탐색용 예측·분석만 허용하며, 엄격한 피드백 확정에는 새 fit-only 산출물이 필요합니다. 새 산출물도 현실 시설에 대한 독립적인 성능 보장은 아닙니다.

재생은 원시 관측과 같은 정책으로 검증한 **정제 CSV의 유효 관측만** 사용합니다. 불능 관측을 빈방으로 예측하지 않으며 제외 개수·사유를 실행 정보에 표시합니다. 기본 300행은 파티션별 희귀 생활 사건과 유효 센서 오류를 우선 확보한 뒤 나머지를 방 파티션별로 분산 추출합니다. 작은 예산이나 제외로 빠진 유형은 `sampling.coverage`의 포함/미포함 행수로 확인합니다. 과대표집과 강제 예외가 포함되므로 지표를 자연 발생 비율의 성능으로 해석하면 안 됩니다. 학습 후보 확정 후에도 `coverage`를 기록하며 사건/이웃 행을 다른 파티션으로 이동하지 않습니다. 중복 제거·최종 보충 예산을 적용한 실제 학습 행의 유형은 데이터플랜 `log_data.selected_coverage`에 기록하고 빠진 유형은 경고합니다.

생성 작업 기록·표준 출력은 `state/generation_jobs`에 남고 API 재시작 뒤에도 조회할 수 있습니다. 중단된 프로세스는 실패 상태로 표시해 재시도할 수 있게 합니다. 생성물은 최초·파일 변경 시 전체 해시를 검증하고, 이후에는 파일 식별자·크기·수정/변경 시각을 확인해 같은 내용을 재파싱하지 않습니다. 예측 로그는 SQLite의 미전송 행만 기록하고 기록 후 전송 확인을 남깁니다. 일반 로그 쓰기와 중복 방지 쓰기는 같은 파일 잠금 안에서 공통 꼬리 복구를 수행합니다. 완성된 JSON은 줄바꿈만 보완하고, 잘린 JSON/UTF-8은 `*.jsonl.partial-<해시>.bin`에 원본 바이트를 먼저 보존한 뒤 기록합니다. 격리 저장이 중단되면 원본을 자르지 않고 재시도하며 유효한 기존 행과 중복 키를 유지합니다. 정상 로그의 꼬리 확인은 1바이트만 읽고, 같은 logger의 정상 쓰기는 중복 캐시를 갱신해 불필요한 전체 스캔을 피합니다. 일반 쓰기는 실패 시 `False`와 stderr, 중복 방지 쓰기는 실패 시 예외·이미 기록된 키에는 `False`라는 계약을 유지합니다.

Python 환경에서 생성기만 직접 실행할 수도 있습니다(`numpy`, `scipy`, Windows의 `tzdata` 필요). fit-only CLI 실행은 같은 학습 검증 비율로 환경변수를 지정합니다.

```cmd
set SIM_CALIBRATION_SCOPE=fit_only
set SIM_VALIDATION_RATIO=0.2
python scripts/simulate.py
```

## 고정 조건 실제 피드백 실험

`scripts/experiment_feedback.py`는 **실제 기준 학습 1회 + 독립 가상 정답 로그 피드백 재학습 1회**만 수행합니다. 실제 학습이 실행되는 명령입니다. 다른 실험을 반복하거나 test 결과로 설정을 자동 조정하지 않습니다.

```cmd
docker compose run --rm --no-deps -e FEEDBACK_EXPERIMENT_ID=feedback-demo-001 trainer python -m scripts.experiment_feedback
```

실험 ID는 매번 새로 지정합니다. 같은 ID의 보고서나 가중치가 있으면 덮어쓰지 않습니다. 두 모델은 seed 42, 200 epoch, 조기 종료 없음, 동일 피처·MLP·Adam 설정으로 각각 처음부터 학습하고 실제 validation 손실로 가중치를 선택합니다. 기준은 실제 fit만, 후보는 같은 실제 fit과 train 파티션의 최대 600개 정답 연결 관측을 사용합니다. 실제 validation·test는 학습 보충에 넣지 않습니다. 생성기는 fit-only, 생활 예외 집중·관측 스트레스 모드이며 재생은 고정 3,000행입니다.

두 학습 중 실제 test의 지표는 보류하고, 후보까지 학습을 마친 후 같은 실제 test와 동일 고정 합성 heldout을 비교합니다. 중간 private 버전의 `test_evaluation_status: pending`은 이 보류 상태입니다. 보고서에는 precision/recall/F1·혼동행렬·출처/사건/센서 오류별 결과·빈방 점등 오탐/재실 누락·성능 저하도 그대로 기록합니다. 기존의 무정답 시연 로그는 학습 정답으로 사용하지 않습니다.

가중치는 `models/weights/experiments/<실험ID>/v1`·`v2`, 버전 보고서와 최종 비교는 `reports/experiments/<실험ID>/`에 저장합니다. 이 아래 `state/simulated`, `state/pipeline.sqlite3`, `logs`에 원시/정제 데이터·관측·독립 가상 정답·실제 예측 로그를 보존합니다. 격리한 버전명은 기존 전역 v1/v2와 다른 경로이며 기본 `current.json`을 변경하지 않습니다. `experiment.json`·`experiment.md`·`synthetic_comparison.json` 및 버전별 `training.json`에서 설정·학습 횟수·해시·선별/제외량을 확인합니다.

현재 구현은 **BCE 이진분류 지도학습 재학습**입니다. RL의 행동·보상·정책 갱신은 구현되어 있지 않으므로 강화학습 테스트는 실행하지 않습니다. RL을 추가하려면 제어 행동, 독립 환경 전이, 보상과 제약을 먼저 정의해야 합니다. 합성 heldout 향상은 실제 강의실 성능을 보장하지 않습니다.

완료된 실험의 학습 재현성만 확인하려면 아래 명령을 사용합니다. 기준과 후보를 각각 1회씩 추가 학습해 가중치·표준화 통계·학습 이력을 비트 단위로 대조하고, 실제 test 평가는 하지 않습니다. 이 2회는 최초 비교 학습 2회와 별도입니다. 원래 결과와 가중치를 보존하며 `reproducibility.json`이 있으면 자동 반복하지 않습니다.

```cmd
docker compose run --rm --no-deps -e FEEDBACK_EXPERIMENT_ID=feedback-demo-001 -e FEEDBACK_VERIFY_ONLY=1 trainer python -m scripts.experiment_feedback
```

대량 합성 CSV·SQLite·원시 로그·실험 가중치는 Git에서 제외합니다. 공유할 결과는 `summary.json`·`experiment.md`·`reproducibility.json`처럼 입력 원문이 없는 작은 요약만 개별 확인 후 포함합니다. `feedback-20261117-f172d336`의 기준/후보는 새로 학습한 격리 모델이며 운영 v7과의 성능 비교가 아닙니다. 실제 test 정확도는 95.62%→95.93%였지만 합성 빈방 점등 오탐은 60→88건으로 늘었고, 어두운 재실 47건은 모두 놓쳤습니다. 전체 정확도만으로 운영 승격하지 않습니다.

## 읽기 전용 로그 진단과 배포 확인

`scripts/analyze_logs.py`는 JSONL을 수정하지 않고 파싱 오류·출처·중복 inference ID·결측/불능 센서·시각 범위·정답 적격성을 집계합니다. 입력은 운영 EC2에서 복사한 로그(`ec2_runtime`), 로컬 시연(`local_runtime`), 합성 실험(`synthetic_experiment`)을 서로 다른 폴더와 출처로 구분합니다. 운영 원본은 삭제·수정하지 않으며 수집에 실패한 경우 로컬 로그를 운영 로그로 대신 표기하지 않습니다.

```cmd
set LOG_AUDIT_ROOT=/app/reports/operations/downloaded-logs
set LOG_AUDIT_ORIGIN=ec2_runtime
set LOG_AUDIT_OUTPUT=/app/reports/log-analysis/ec2-summary.json
docker compose run --rm --no-deps -e LOG_AUDIT_ROOT -e LOG_AUDIT_ORIGIN -e LOG_AUDIT_OUTPUT trainer python -m scripts.analyze_logs
```

진단 결과에는 원문 필드·파일 경로·요청 내용 대신 집계와 파일 해시만 저장합니다. 독립 생성물에서 검증한 ID·원시각·입력·가상 정답과 정확히 대조한 train 관측만 학습 후보가 될 수 있습니다. CLI 단독 실행은 이 검증 맵이 없으므로 후보 0행으로 보수적으로 처리합니다. `label_source=model_prediction`이나 로그 안에 임의로 추가한 `ground_truth`는 정답으로 인정하지 않습니다. 실제 학습은 PipelineStore의 manifest·행·정답 재검증 및 데이터 확정 경로를 사용합니다.

자동 배포는 기존 workflow의 main push/dispatch 및 `EC2_DEPLOY_ENABLED=true` 조건을 충족해야 하며 PR에서는 배포하지 않습니다. 배포 전에는 접근 가능한 SSH/공개 API, 서버 Git origin에 대상 SHA가 존재하는지, workflow `EC2_HTTP_PORT`와 서버 HTTP 포트의 일치, 실제 실행 이미지 revision과 배포 marker의 일치를 확인해야 합니다. test 성공만으로 운영 배포 완료를 뜻하지 않습니다. 신규 파이프라인 테스트 `backend.test_pipeline`와 로그 진단 테스트 `scripts.test_analyze_logs`의 CI 선택 목록 반영도 CI 담당자가 확인해야 합니다.

후보 승격은 고정 자료의 성능과 빈방 점등·재실 누락 회귀를 함께 검토한 뒤 수동 결정합니다. 코드 배포·모델 승격·화면 렌더 검증은 별개이며, API HTTP 200이나 JSON 응답을 화면 캡처로 간주하지 않습니다. 실제 재배포 전에는 현재 이미지 SHA/모델 SHA/current 포인터와 상태·로그·가중치·보고서 볼륨을 보존하고, 기존 `deploy/deploy.sh`의 이전 커밋 복구 및 헬스체크 절차를 준비해야 합니다.

## 모델 버전과 저장 구조

**버전은 학습된 모델과 그 설정을 뜻합니다.** 웹에서 명시적으로 학습하여 성공할 때마다 다음 `vN`을 등록합니다. 동일한 설정과 가중치로 재현된 실험도 새 학습 이력으로 보존하며, 같은 가중치인지 식별값으로 표시합니다. 화면·폴더 변경이나 Compose 재실행만으로 버전을 만들지 않습니다.

기존 v1~v3 가중치를 덮어쓰지 않습니다. `models/weights/current.json`은 기본 모델을 가리킵니다. 학습 완료 시 기본 적용을 켜거나 대시보드의 **기본 모델로 사용** 버튼을 누르면 다른 팀원의 버전 없는 예측 요청에도 해당 모델이 적용됩니다. 화면에서 실험 버전만 선택하면 해당 브라우저의 실험 대상만 바뀝니다.

정확도가 85% 미만인 피처 실험도 저장하고 기준 미달로 표시합니다. 피처의 영향을 비교하기 위한 학습을 정확도 기준으로 차단하지 않습니다. 최초 기본 모델을 준비할 때만 기존 85% 정확도 기준을 적용합니다.

API는 모델·스크립트 코드와 원본 데이터를 읽기 전용으로 마운트하며, 가중치·보고서·로그 경로에만 결과를 씁니다. 개발 환경에서 바인드 마운트의 파일 권한 차이를 줄이기 위해 trainer와 API는 컨테이너 root로 실행합니다. 애플리케이션 루트 파일시스템은 읽기 전용이고 임시 파일은 `/tmp`를 사용합니다. 프런트는 프로덕션 빌드하지 않습니다.

## 예측 입력

| 필드 | 의미 | API 범위 |
|---|---|---|
| `Temperature` | 기온, °C | -50~60 |
| `Humidity` | 상대습도, % | 0~100 |
| `Light` | 조도, lux | 0~1,000,000 |
| `CO2` | CO₂, ppm | 0 초과~1,000,000 |
| `Hour` | 측정 시간, 시 | 정수 0~23 |
| `DayOfWeek` | 측정 요일 | 정수 0~6, 월 0~일 6 |

예: 모델의 시간 기준에서 수요일 오후 2시는 `Hour: 14`, `DayOfWeek: 2`입니다. 새 학습은 위 `source-local-time-v1` 정책으로 CSV 출처의 현지 시각을 추출합니다. 시간은 24시간 주기의 sin/cos, 요일은 7일 주기의 sin/cos와 주말 여부로 변환하며 학습·추론이 같은 함수를 사용합니다. 선택에서 제외한 피처는 실제 신경망 입력에 들어가지 않습니다. 예측 API는 모든 버전에서 같은 6개 필드를 받고 모델의 피처 목록에 없는 값은 무시합니다.

```cmd
curl http://localhost:8000/compare --json @backend/examples/mock_sensor.json
curl http://localhost:8000/compare?version=v3 --json @backend/examples/mock_sensor.json
```

응답의 `with_light`는 기존 API 호환을 유지하는 **선택 모델** 키입니다. 새 실험에서는 해당 모델도 조도를 포함하지 않을 수 있으므로 `/metrics`의 `features`를 확인합니다. `without_light`는 비교 모델을 저장한 버전에만 반환합니다. `/predict`는 선택 모델 하나의 `model_version`, `occupancy`, `label`, `probability`를 반환합니다. `mode=without_light`로 비교 모델을 직접 요청할 수 있습니다.

누락·추가 필드, 문자열 숫자, 참/거짓 숫자, 범위 오류, NaN·무한대는 HTTP 400, 없는 버전·작업·비교 모델은 HTTP 404입니다. 외부 예측 API는 위 물리 범위를 유지합니다.

웹 센서 실험과 미리보기는 **선택 모델이 실제 fit에 사용한 행의 관측 범위**로 제한합니다. 새 학습은 float32 변환 전 센서 최솟값·최댓값과 시간·요일 관측값을 체크포인트·보고서의 `input_limits`에 저장하므로 이후 CSV를 갱신해도 유지됩니다. 검증·평가 행은 범위 계산에 쓰지 않습니다. 기존 버전은 저장 당시 CSV 해시와 연속 학습 구간을 검증하여 복원하며, 검증할 수 없으면 입력을 차단하고 사유를 표시합니다. `/versions/{version}/training`에서 모델별 범위를 확인합니다.

범위 밖 예제는 이유와 함께 비활성화하고, 버전 전환 후 기존 입력이 범위 밖이면 수정 전까지 예측을 막습니다. 범위를 확인할 수 없는 버전도 예측을 비활성화합니다. 선택 모델이 사용하지 않는 필드는 API 계약을 맞추기 위한 유효한 기본값으로 보내며 해당 모델의 예측에 사용하지 않습니다. 모델 모드를 바꾸면 다시 예측해야 합니다. 관측 범위 안이라는 사실이 정확도를 보장하지는 않습니다.

## 데이터와 성능 해석

- 학습 파일 32,387건, 별도 평가 파일 18,479건입니다. 검증 비율은 학습 CSV 내부의 기존 자료·Room A·Room B 각각을 시간순 fit/validation으로 나눕니다. 출처는 신경망 입력에 추가하지 않습니다.
- 기존 학습 8,143건과 평가 12,417건의 행·역할을 유지하고 새 자료 30,306건을 추가했습니다.
- 새 자료는 두 방을 합쳐 시간순 앞 80%인 24,244건을 학습에, 뒤 6,062건을 평가에 배치했습니다. 경계의 같은 시각은 모두 평가 쪽에 둡니다.
- 같은 출처의 동일 시각 그룹을 fit/validation 경계 양쪽에 나누지 않습니다. 출처가 다른 행끼리는 시각이 겹칠 수 있습니다. 평가 파일은 fit/validation에 포함하지 않으며 같은 출처·시각이나 동일 기록이 학습·평가 파일에 겹치면 학습을 거부합니다.
- 웹에서 검증 비율을 바꾸면 실제 출처별 fit/validation/test 행수와 클래스 분포를 표시합니다. 빈 분할·전체 클래스 부재 등 학습 불가능한 설정은 시작 전에 차단합니다. 단일 클래스 출처 부분집합은 경고하고 ROC-AUC·평균 정밀도를 `null`로 기록합니다.
- 완료 보고서에는 전체 지표와 출처별 행수·클래스 분포·정밀도·재현율·F1·혼동 행렬을 기록합니다. 대시보드의 최고값·차트는 평가 CSV SHA-256와 행수가 같은 버전끼리만 비교합니다.
- 기존 v3의 당시 평가 12,417건 지표는 조도 포함 98.96%, 제외 85.17%입니다. 갱신된 18,479건 평가 자료나 변경된 설정의 성능을 이 값으로 보장하지 않습니다.
- 정확도뿐 아니라 정밀도·재현율·F1·혼동 행렬·학습 기간 이후 지표도 확인합니다. 예컨대 모두 비어 있음으로만 예측해도 데이터 분포 때문에 높은 정확도가 나올 수 있습니다.
- 평가 정답으로 가중치나 임계값을 자동 선택하지 않습니다. 같은 평가 파일을 보며 반복 실험하는 동안 평가에 적응할 수 있으므로 최종 성능은 새 데이터로 검증해야 합니다.

이 모델은 현재 재실 판별이며 미래 예약·미래 사용 여부를 예측하지 않습니다.

추가 데이터 반영은 모델 학습과 별개입니다. `scripts/merge_data.py`를 Python으로 실행하면 `intermi/Room_A`, `Room_B`의 `df_features.csv`와 `df_occ.csv`를 시각으로 연결하고 공통 센서 4개만 추출하여 기존 CSV를 갱신합니다. 이미지 정답의 0명은 비어 있음, 1명 이상은 사용 중으로 변환하며 UTC 시각을 유지합니다. 유효하지 않은 센서·정답은 제외 건수로 표시하고 재실행은 중복을 추가하지 않습니다. 원시 데이터와 ZIP은 읽지 않으며, 학습은 웹에서 별도로 시작합니다.

`data/dataset_sources.json`은 CSV 행 순서에 맞춘 출처와 CSV SHA-256을 보존합니다. 같은 시각의 두 방은 전체 센서·정답과 발생 순번으로 연결합니다. CSV와 출처 파일은 함께 공유하며, 불일치하면 학습을 차단합니다. 기존 CSV만 있고 출처 메타데이터가 없는 단일 출처 자료는 `legacy`로 취급합니다.

이 세 데이터 파일은 `.gitattributes`로 Git의 줄바꿈 자동 변환을 끕니다. Windows와 Linux에서 체크아웃한 바이트·SHA-256이 같아야 출처 검증을 통과할 수 있습니다.

`models/prepare_data.py`와 `graz_*.csv`는 이전 v7의 전처리·평가 자료로 보존하며 현재 학습 경로에는 연결하지 않습니다. 기본 학습은 통합 CSV 두 개와 출처 메타데이터를 사용하며, 웹에서 검증된 생성 데이터를 선택한 경우에만 실제 fit에 합성 행을 보충합니다. v7 가중치·보고서는 읽을 수 있지만 원본 학습 범위를 검증할 수 없으면 입력 제한을 복원하지 않습니다. 이전 설정을 불러올 때는 현재 API가 지원하는 항목만 적용하고, 이전 전용 데이터 선택 옵션은 제외했다고 표시합니다.

## 독립 가상 센서 CSV 생성기

`scripts/simulate.py`는 분류 모델 학습과 분리된 확률적 상황·동적 센서 생성기입니다. 원본행을 재생하지 않고 새 인원·전등·환기 상태를 만든 뒤 CO₂ 질량수지, 일광·날씨·방 특성, 냉난방·온습도 반응과 센서 공분산 기반 시간상관 잡음으로 센서를 계산합니다. `Occupancy`는 가상 인원수가 0명보다 큰지로만 정합니다.

### 빠른 시작

**웹·API·가중치 없이 스크립트 하나만 실행하면 CSV가 생성됩니다.** Python 환경에서는 저장소 루트에서 실행합니다. 패키지 설치는 최초 한 번 필요하며 스크립트 자체는 `.env`를 읽지 않고 현재 환경변수와 기본값을 사용합니다.

```cmd
python -m pip install numpy scipy tzdata
python scripts/simulate.py
```

피드백 재학습에 사용할 새 결과는 `SIM_CALIBRATION_SCOPE=fit_only`와 학습 화면의 검증 비율에 맞는 `SIM_VALIDATION_RATIO`를 지정하세요. 기본 canonical 생성물은 기존 호환성을 유지하지만 실제 validation의 보정 통계를 포함하므로 피드백 확정에 사용할 수 없습니다.

Docker 환경을 쓰려면 아래 명령을 실행합니다. 웹·API를 먼저 띄울 필요가 없습니다.

```cmd
docker compose build simulator
docker compose run --rm --no-deps simulator
```

이미지를 준비한 뒤에는 두 번째 명령만 실행하면 됩니다. 빌드는 학습을 실행하지 않습니다. `simulator`는 선택적인 `simulation-tools` 프로필에만 속하고 일반 `docker compose up`에는 실행되지 않습니다. API·trainer를 의존 서비스로 시작하지 않고 원본 데이터는 읽기 전용, `data/simulated`만 쓰기 가능하게 마운트합니다.

필수 입력은 저장소의 `data/training_dataset.csv`와 `data/dataset_sources.json`입니다. `data/occupancy-detection-dataset/data/intermi/Room_A`·`Room_B`의 `df_occ.csv`와 `df_features.csv`가 있으면 학습 행에 해당하는 영상 인원수·개구부 정보도 사용합니다. 각 방의 두 보조 파일이 모두 있지 않으면 해당 방의 인원수·개구부는 가정으로 대체하고 출처에 기록합니다.

기본값은 seed **20261111**, **3개 방·2026-11-09부터 7일·1분 간격·Asia/Seoul**, **예외 집중 모드**입니다. 결과는 `data/simulated/<생성ID>/`에 저장합니다. 같은 코드·자료·seed·설정이면 CSV와 의미상 메타데이터가 재현되며 같은 생성ID가 이미 있으면 덮어쓰지 않고 실패합니다. 새 결과가 필요하면 seed나 생성 설정을 변경합니다. 출력은 Git에서 제외합니다.

- 방별 `room_01.csv` 등의 열은 기존과 같은 `date,Temperature,Humidity,Light,CO2,Occupancy` 6개뿐입니다. 날짜는 offset을 포함한 ISO 시각이고 센서 단위는 °C, %, lux, ppm입니다.
- `room_01.metadata.jsonl` 등은 CSV 파일명·0부터 시작하는 행 인덱스·실제 CSV 행번호·고유 ID로 연결합니다. 가상 인원·전등·환기·사건·합성 표시와 방/날짜 그룹은 이 파일에만 있습니다. 모델 입력으로 합치지 마세요.
- `manifest.json`에는 설정·seed·코드/프로필/보정자료 해시·시간대·실제 사건 건수·분할 권고를 기록합니다. `profile.json`에는 출처별 보정 통계와 추정/가정 구분, `quality.md`·`quality.json`에는 생성 품질의 요약·수치를 기록합니다. `INCOMPLETE`가 있으면 완료되지 않은 결과입니다.

### 관측 센서 오류와 정제 정책

물리·생활 시나리오 다음에 별도 seed의 관측 계층을 적용합니다. 새 생성물(`observation_schema: 2`)은 양자화, 지속 값 고정, 일시 급등/급락, 느린 편향, 센서 결측, 수집 중단, 비유한값을 재현합니다. 빈방 점등·퇴실 후 CO₂ 잔류 같은 **유효한 생활 예외와 센서 오류는 별도 태그**로 기록합니다. 관측 오류를 켜도 가상 인원수 정답은 바뀌지 않습니다.

- `room_01.raw.csv`: 수신된 원시각·원값. 결측은 빈 칸, 비유한값은 `nan`/`inf` 문자열로 보존하며 수집 중단 구간은 행 자체를 기록하지 않습니다.
- `room_01.observations.jsonl`: 예정 시각별 stable 관측 ID, 수신 여부, 원시/정제 행번호, 처리 전후값, 독립 인원수 정답, 오류 유형·episode ID, 제외 사유를 연결합니다. manifest의 `sensor_faults`에 오류 시작/종료·기간·강도를 기록합니다. 중단된 시각은 감사 기록이며 측정값이 아닙니다. JSON에는 NaN/Infinity 숫자를 쓰지 않습니다.
- `room_01.csv`·`room_01.metadata.jsonl`: 전처리를 통과한 학습·재생 공용 파일. 기존 6열 계약을 유지하며 제외로 시간 간격이 벌어질 수 있습니다. loader는 감사 기록의 원래 고정 간격과 제외 내역까지 대조합니다. 구버전 생성물의 고정 간격 계약도 계속 지원합니다.

전처리는 **보간·대체·클리핑 없이 제외**하는 정책입니다. 결측·비유한·숫자 아님·관측 한계 밖 값(온도 -20~45°C, 습도 1~99%, 조도 0~20,000lux, CO₂ 250~10,000ppm)이 하나라도 있거나 수집 중단이면 추론·학습에서 제외합니다. 이는 생성기용 명시적 관측 한계이며 일반 API 입력 범위와 다릅니다. 유효 범위의 고정값·급등락·편향은 유지합니다. 정답 0은 결측과 구분하며 인원수·정답·오류 태그를 모델 입력에 넣지 않습니다. 미래/validation/test 값은 전처리에 사용하지 않습니다.

센서 해상도는 선택한 보정 구간의 98% 이상이 정렬되는 격자로 추정하고, 근거가 없으면 0.001을 가정합니다. fit-only에서는 실제 fit만 분석합니다. `profile.sources.*.observation_calibration`에 정체 구간·경계값·결측 진단을 함께 기록합니다. **정체는 고장인지 전처리의 값 채움인지 원인을 단정할 수 없습니다.** 발생률·지속 시간은 측정된 고장률로 추정하지 않습니다. 기존 canonical과 raw 선택 센서에서 결측이 없었다는 사실도 가상의 장애 확률 근거로 사용하지 않습니다.

관측 오류 설정은 `SIM_OBSERVATION_MODE=off|normal|stress`입니다. 기본 `normal`은 `SIM_FAULT_PROBABILITY=0.03`의 **오류 유형·방·날짜별 가정 확률**, `stress`는 각 방에 6종 오류를 한 번씩 강제 배치, `off`는 관측 계층을 끕니다. 지속 시간 기본 가정은 `SIM_FAULT_MIN_MINUTES=30`, `SIM_FAULT_MAX_MINUTES=180`(설정 범위 5~2,880분)이며 스파이크는 1~3표본입니다. 생활 모드 `SIM_MODE=exceptions`와 독립된 설정이며 어느 쪽의 빈도도 실제 발생률 보장이 아닙니다. 웹에서도 일반/스트레스/끄기를 선택할 수 있습니다.

`quality.json`의 `observation.raw/clean`은 실제 파일에서 결측·비유한·중복/역전·시간 공백·정체 구간·관측 한계 밖/경계값을 집계합니다. `partition_events`는 유형·파티션별 예정/정제 행수, 각 방은 처리율·제외 사유·오류 기간을 기록합니다. `boundary_hits`는 경계 관측 수이며 클리핑 횟수가 아닙니다. 동역학 통계는 오류 전 물리 궤적(`dynamics_scope`)으로 별도 표시합니다. `quality.passed`는 제한된 구조·출처·정답·전처리 검사 통과이며 현실성 인증이나 모델 성능이 아닙니다.

생활 예외 집중 모드는 각 방에 7종 사건을 독립 seed·시각·강도로 배치합니다. 방 전체를 train/validation/test로 분할해 같은 episode나 인접 행이 분할을 넘지 않습니다. 보정 자료는 소수 인원의 사무실 관측이므로 대형 강의실·다른 환기량·계절의 현실성이나 실제 성능을 보장하지 않습니다. 기존 생성물·실제 CSV·모델 가중치는 자동 수정하거나 합치지 않습니다.

설정은 Compose가 읽는 `.env.example` 기본값과 사용자가 관리하는 `.env`의 `SIM_*` 환경변수로 전달합니다. 생성기 자체는 `.env`를 직접 열지 않습니다. `SIM_MODE=normal`은 일반 생활 패턴과 가정한 드문 사건, `exceptions`는 주말 무인 점등·22시 무인 점등·소등 누락·야간 실제 사용·어두운 재실·강한 환기 중 재실·퇴실 후 CO₂ 잔류를 의도적으로 포함합니다. 강제 비율은 실제 발생률이 아닙니다.

예를 들어 일반 모드로 3개 방의 14일 데이터를 새로 만들려면, 기존 `.env`의 다른 설정은 유지하고 아래 항목만 추가하거나 수정한 뒤 생성 명령을 다시 실행합니다. `.env`가 없으면 위 실행 절의 복사 명령으로 처음 한 번만 만듭니다.

```dotenv
SIM_MODE=normal
SIM_SEED=20261112
SIM_ROOMS=3
SIM_DAYS=14
SIM_START_DATE=2026-11-09
SIM_STEP_SECONDS=60
SIM_TIMEZONE=Asia/Seoul
```

명령이 성공하면 마지막 출력의 `passed: true`와 생성 경로를 확인하고 해당 폴더의 `quality.md`를 먼저 읽습니다. 실패 시 남는 `INCOMPLETE` 결과는 학습에 사용하지 마세요. 같은 설정으로 생성된 폴더가 이미 있다면 오류는 덮어쓰기 방지 동작이며, 다른 seed로 새 실험을 만들 수 있습니다.

`SIM_ROOMS`는 1~12, `SIM_DAYS`는 1~31(예외 집중은 7일 이상), `SIM_STEP_SECONDS`는 30/60/300입니다. `SIM_START_DATE`, `SIM_TIMEZONE`, `SIM_SEED`로 달력과 재현성을 정합니다. `SIM_CAPACITY` 기본 8명, `SIM_VOLUME_M3` 기본 90m³, `SIM_LATITUDE` 기본 37.5도는 실제 방에서 식별한 값이 아닌 조정 가능한 가정입니다. 일반 모드의 `SIM_EVENT_PROBABILITY` 기본 0.03은 방·날짜별 가정한 예외 확률입니다.

보정 기준은 **canonical `training_dataset.csv` 한 벌**이며 기존 `test_dataset.csv`와 중복 파생본은 분포 추정에 사용하지 않습니다. `dataset_sources.json` 해시·출처를 검증하고 Graz 보조정보도 학습 출처·시각·센서·영상 정답이 일치하는 부분만 연결합니다. 보조 특징의 `occupancy` 센서는 영상 인원수 정답과 구분합니다. Graz는 UTC에서 Europe/Vienna로 변환하고 legacy는 시간대 미확인 현지 시각으로 분석합니다. 1분/5분 표본 간격을 분당 변화량으로 맞추며 다른 날짜·출처·큰 공백은 차분에서 제외합니다. DST가 있는 생성 시간대도 UTC 경과로 처리합니다.

품질 검사는 실제 내보낸 파일을 다시 읽어 스키마·유한값·범위·시간·정답·사건 일관성을 확인합니다. 분포·증감·자기상관·센서 상관·사용 지속시간 차이를 수치화하고, 타임스탬프를 무시한 센서 행/8시점 윈도우의 동일·근접 복사를 검사합니다. 윈도우 근접 검사는 출처의 원래 표본 간격에 맞춘 15분 간격 표본 진단이며 현실성의 증명은 아닙니다.

향후 합성 학습/평가에는 `manifest.json`의 전체 방 단위 분할 권고를 사용하세요. 같은 날짜·사건·인접 행이 분할을 넘지 않습니다. 방이 3개 미만이면 `train_only`만 제안합니다. 방별 보정 출처가 다르므로 분할에는 출처 차이도 포함됩니다. **현재 생성기는 자동 학습·평가·기존 CSV 병합을 하지 않습니다.** 사무실 관측을 새 방에 옮긴 가정이므로 실제 강의실·대규모 인원·환기량·계절의 현실성이나 모델 성능을 보장하지 않습니다.

```cmd
docker compose run --rm --no-deps simulator python -m unittest scripts.test_simulate -v
```

## 검증과 중지

```cmd
docker compose exec -T api python -m unittest backend.test_data backend.test_logging backend.test_classrooms -v
docker compose ps -a
docker compose stop api web
```

데이터·로그 fixture는 학습·추론·정확도 계산을 실행하지 않습니다. 강의실 검사는 일부 흐름에 저장 모델의 단건 추론을 사용하며 학습·정확도 평가는 하지 않습니다. 학습 테스트는 사용자가 별도로 선택할 때만 다음 명령으로 실행합니다. 임시 경로에 실제 모델을 학습하므로 단순 빌드·데이터 검사에 포함하지 않습니다.

```cmd
docker compose exec -T api python -m unittest backend.test_app.TrainingTests -v
```

`backend.test_app` 전체 실행도 실제 학습을 포함합니다. 백엔드 패키지와 프런트 npm 잠금 파일은 고정했으며 가중치는 `torch.load(weights_only=True, map_location="cpu")`로 로드합니다.

## 실행별 로그

API worker의 초기화 시각(`backend.app` 로드 시각)을 기동 기준으로 사용합니다. API 시작 시 자동으로 `logs/20261028T120000_000000Z-<실행ID>/` 같은 폴더를 만들고, `Z`는 UTC를 뜻합니다. 재시작·개발 reload는 새 실행 ID를 사용하며 과거 로그를 덮어쓰거나 자동 삭제하지 않습니다. 기존 기본 모델을 사용하는 런타임 trainer는 추가 학습을 하지 않습니다. 기본 모델이 없어 직접 초기 학습을 수행하는 경로는 별도 실행 ID를 사용합니다.

- `api.jsonl`: 서버 시작·종료, 요청 ID, UTC 시각, HTTP method·경로·라우트, 상태 코드·처리시간, 오류 유형·검증 오류 필드입니다. healthcheck도 기록하며 Authorization·Cookie·쿼리 문자열·요청/응답 본문 전체를 덤프하지 않습니다.
- `model.jsonl`: `event_type=inference`는 검증된 실제 센서 입력, 버전·모드·피처·임계값·가중치 쌍 fingerprint와 예측 결과를 기록합니다. `/compare`도 각 모델 결과를 같은 request ID에 연결하고 결과마다 inference ID를 부여합니다.
- `event_type=training`은 향후 학습 실행 때 작업 ID, 설정·시드, 실제 데이터 해시·출처별 분할, 에포크 손실, 완료 버전·평가 결과, 중지·실패를 기록합니다. 배치마다 대형 로그를 남기지 않으며 작업 상태와 실행 stdout/stderr는 기존 `reports/jobs`에도 유지합니다.

자식 학습 프로세스에는 부모 API의 실행 ID·로그 경로·요청 ID를 전달합니다. API가 재기동되어도 이미 시작한 작업은 원래 실행 폴더에 계속 기록합니다. 로그 행은 `schema_version=1` 및 run/request/job/inference 식별값으로 연결하며, 프로세스 간 파일 잠금과 매 기록 후 flush를 적용합니다. 기록 실패는 stderr에 표시하고 정상 예측이나 학습 결과 저장을 막지 않습니다. `logs/`는 쓰기 가능한 별도 Docker bind mount이고 코드·Compose가 필요한 폴더를 생성합니다.

**예측 결과는 정답이나 강화학습 보상이 아닙니다.** 현재 실제 정답·행동·보상 수집은 없으며 로그에 이를 추정해 넣지 않습니다. 이 로그만으로 강화학습 데이터가 완성되지는 않습니다. 이후 실제 관측·정답·보상을 식별값으로 연결해야 합니다.

API 로그와 모델 로그는 운영 추적뿐 아니라 **학습 설정·데이터·버전·사용 피처·센서 입력·예측 결과를 연결하여 향후 재학습과 강화학습용 데이터 구성을 위한 기반**으로 남깁니다. 강의실 측정은 classroom/measurement/inference/session 식별값을 추가하며 시연 합성 자료를 실제 관측 정답으로 취급하지 않습니다.
