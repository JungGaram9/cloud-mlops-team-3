# 강의실 지킴이 · 사용 현황과 모델 관리

첫 화면에서 경비원이 여러 강의실의 **모델이 추정한 사용 상태**를 확인하는 서비스입니다. 현재는 시연 명칭의 101~103호·201~203호 6개와 가상 센서 데이터를 사용하며, 실제 센서 수신 API도 제공합니다. 기존 학습·평가·버전·단건 예측 기능은 **모델 관리** 영역에 보존합니다. FastAPI는 Swagger UI를 제공하고 React 화면은 **Vite 개발 서버**를 사용합니다. 로그인·권한 제어는 구현하지 않았습니다.

## 실행

Docker Desktop의 Linux 컨테이너 엔진과 Docker Compose 2.24 이상이 필요합니다. Python·Node·가상환경을 별도로 설치하지 않습니다. 저장소 루트의 CMD에서 실행합니다.

```cmd
docker compose up -d --build
```

- [웹사이트](http://localhost:5173/): 강의실 현황 / 모델 관리(대시보드·센서 실험·모델 학습).
- [Swagger UI](http://localhost:8000/docs): API 입력 규격과 실제 요청.

이미지 빌드에서는 모델 학습·평가·테스트를 실행하지 않습니다. 런타임에는 기본 모델 준비 → API 준비 → Vite 실행 순서이며 trainer의 `Exited (0)`은 정상입니다. 저장된 기본 모델이 있으면 그대로 사용하고, 기본 모델이 없는 초기 런타임에만 trainer가 학습합니다. 처음 이미지와 패키지를 받을 때 인터넷이 필요합니다.

```cmd
docker compose ps -a
docker compose logs --tail 50 trainer api web
```

Compose는 루트 `.env`를 자동으로 적용하고, 없으면 `.env.example` 기본값을 사용합니다. 포트 변경은 사용자가 직접 `.env`의 `API_PORT` / `WEB_PORT`를 수정합니다. 처음 생성할 때만 아래 명령을 사용합니다.

```cmd
copy .env.example .env
```

`.env`는 Git에서 제외하며 애플리케이션 코드에서 직접 읽지 않습니다. 웹의 `/api` 요청은 내부 API로 프록시하므로 API의 호스트 포트를 바꿔도 프런트 수정이 필요 없습니다. 호스트 포트는 `127.0.0.1`에 연결됩니다.

## 경비원용 강의실 현황

전체·사용 중·비어 있음·확인 필요 수와 방별 층·상태·마지막 실제 수신 시각을 확인합니다. 이름 검색과 층·상태 필터를 제공하며 상세에는 센서 4종, 측정 시각, 실제 사용 모델·추정 확률, 최근 센서 변화와 판별 이력을 표시합니다. 재실 추정은 예약·출입 가능 여부가 아닙니다. 모델 관리의 데이터 조회 실패나 과거 버전의 입력범위 복원 실패가 강의실 현황을 막지 않습니다.

서버는 **UTC 08:00~22:00** 하루 시연 시계를 공유합니다. 기본 속도는 실제 1초당 시연 5분이며 하루 약 168초입니다. 재생·일시정지·1/5/10/20분 속도·처음부터 제어는 모든 브라우저에 함께 반영됩니다. 페이지나 탭마다 생성기를 만들지 않습니다. 시연이 끝나면 정지하며 처음부터로 새 세션을 시작합니다. API는 하나의 worker로 실행하며, SQLite 서비스 잠금으로 중복 생성기를 방지합니다.

강의실마다 다른 가상 시간표가 조도 상승·퇴실 후 하강, CO₂ 축적·환기 감소와 완만한 온습도 변화에 영향을 줍니다. 센서 궤적은 재현 가능하며 기존 CSV의 대표 범위를 참고했지만 현실에서 검증한 생성 모델은 아닙니다. **화면 상태는 시간표가 아니라 현재 기본 저장 모델의 실제 추론 결과**입니다. 시나리오와 판별이 다를 수 있으며 이를 정확도로 표시하거나 재학습 CSV에 자동 추가하지 않습니다.

수신 없음은 **수신 대기**, 추론 실패는 **판별 불가**, 실제 서버 수신 이후 기본 60초 초과는 **확인 필요**입니다. `SENSOR_STALE_SECONDS`로 지연 기준을 바꿀 수 있습니다. 가상 미래 측정 시각을 신선도 판단에 사용하지 않습니다. 시연 정지·종료 시 마지막 판별을 보존하고 정지 원인을 표시하며 60초가 지나면 지연 상태로 전환합니다. 화면은 1초 간격으로 다시 조회하고 통신 장애 시 마지막 값을 현재 상태인 것처럼 표시하지 않습니다.

### 센서 수신과 시간 계약

`GET /classrooms`는 저장된 최신 상태·공유 시계를, `GET /classrooms/{id}`는 최신 관측·짧은 이력을 반환합니다. 조회 자체는 새 추론을 실행하지 않습니다. `POST /classrooms/{id}/measurements`는 아래와 같이 필수 센서 4종을 받습니다. 누락값은 기본값으로 채우지 않습니다.

```json
{
  "measurement_id": "sensor-101-20261028-0001",
  "observed_at": "2026-10-28T09:00:00+09:00",
  "source": "real",
  "Temperature": 22.0,
  "Humidity": 28.0,
  "Light": 450.0,
  "CO2": 800.0
}
```

`observed_at`은 UTC offset 또는 `Z`가 필수입니다. 원본 시각과 센서값을 보존하며 **UTC로 정규화한 측정 시각에서 Hour·DayOfWeek를 파생**합니다. 새 전처리 자료의 UTC 기준과 맞추며 기존 CSV·가중치의 시간 정의는 바꾸지 않습니다. 화면의 측정·시연 시각은 UTC, 실제 수신 시각은 KST로 명시합니다. `received_at`은 서버의 실제 UTC 수신 시각입니다.

유효한 실센서 측정이 들어오면 해당 방만 실센서 모드가 되어 시연이 덮어쓰지 않습니다. 동일 방·source·measurement_id의 같은 내용은 중복으로 반환하고 다시 추론·반영하지 않습니다. 같은 ID에 다른 내용이면 HTTP 409입니다. 과거·동일 시각의 늦은 측정은 기록하되 최신 상태를 덮어쓰지 않습니다. 응답에는 measurement_id·inference_id·중복 여부·최신 반영 여부가 있어 후속 실제 정답과 연결할 수 있습니다.

`PUT /classrooms/{id}/source`에 `{"source":"simulation"}` 또는 `{"source":"real"}`을 보내 소스를 명시적으로 전환합니다. 전환 직후에는 수신 대기이며 새 측정부터 반영합니다. 상세 화면에서도 전환할 수 있습니다. `POST /simulation/control`은 `action=play/pause/restart/speed`와 필요 시 `speed=1/5/10/20`을 받습니다. 시연에는 scenario/session ID를 보존하고 로그의 `source=simulation/real/experiment`로 시연·센서 수신·모델 관리용 단건 실험을 구분합니다.

상태는 `CLASSROOM_STATE_DIR`(컨테이너 기본 `/app/state`)의 SQLite에 저장합니다. Compose의 `./state:/app/state`는 쓰기 가능하고 Git에서 제외합니다. 각 방의 최신 관측·판별과 최근 96건 본문을 보존하며 중복 측정 ID 원장은 별도로 디스크에 남깁니다. 메모리에 무제한 이력을 누적하지 않습니다. 재기동은 공유 시연 위치·재생 상태·실센서 모드를 복원합니다. 시연은 종료 중 지난 실제 시간을 가상 시각에 더하지 않습니다. 저장소가 준비되지 않으면 현황 API는 사유와 HTTP 503을 반환하고 모델 관리를 계속 제공합니다.

## 모델 관리에서 학습

1. **모델 관리 → 모델 학습** 탭에서 실험 이름을 정합니다.
2. 기온·습도·조도·CO₂·시간·요일의 스위치를 켜거나 꺼 **실제 학습 피처**를 선택합니다. 최소 한 개가 필요합니다.
3. 학습률·에포크·배치·신경망 구조 등을 조정하고 **학습 시작**을 누릅니다.
4. 진행률·학습 손실·검증 손실을 확인합니다. 학습은 별도 프로세스에서 실행하므로 탭 이동과 페이지 새로고침 후에도 계속됩니다.
5. 완료하면 새 `vN`의 가중치와 보고서가 저장됩니다. 대시보드에서 버전을 선택해 설정·정확도·정밀도·재현율·F1·혼동 행렬·학습 곡선을 확인합니다.
6. **설정 불러오기**로 기존 실험을 수정해 다시 학습하거나, **예측 실험**으로 해당 가중치를 테스트합니다. 보고서는 JSON으로 내려받을 수 있습니다.

피처 카드의 센서 슬라이더는 **저장된 모델의 예측 미리보기 입력**입니다. CSV의 모든 행을 동일한 센서값으로 바꾸거나 학습 데이터를 조작하지 않습니다. 하이퍼파라미터 슬라이더는 실제 학습 설정에 적용됩니다. 처음 학습하지 않은 초안 설정으로 예측하는 것처럼 표시하지 않습니다.

조도와 다른 피처를 함께 선택하고 **조도 제외 모델도 비교 학습**을 켜면, 동일한 데이터와 설정으로 조도만 뺀 모델도 학습합니다. 같은 버전 안에 두 가중치를 저장합니다. 조도를 끄거나 조도만 선택하거나 비교 옵션을 끄면 선택한 피처의 모델 하나를 저장합니다. 조도 제외는 `Light=0`을 입력하는 방식이 아닙니다.

동시에 한 학습을 실행합니다. 진행 중 추가 요청은 HTTP 409입니다. **학습 중지**는 다음 배치에서 반영하며, 실패·중지 이력을 남기고 완성되지 않은 모델은 등록하지 않습니다. 저장이 완료된 직후의 중지 요청은 이미 완료된 모델을 취소하지 않습니다. 서버 프로세스가 중단된 작업은 재조회 때 실패 상태로 정리하여 다음 학습을 막지 않습니다.

## 조정 가능한 설정

| 설정 | 기본값 | 허용 범위 / 의미 |
|---|---|---|
| 피처 | 6개 모두 | 6개 중 1개 이상, 중복 불가 |
| 최대 에포크 | 200 | 1~500회 |
| 학습률 | 0.01 | 0.00001~0.1 |
| 옵티마이저 | Adam | Adam / SGD |
| 배치 크기 | 전체 배치 | 0은 전체, 32~8192; 웹은 대표 크기 제공 |
| 은닉층 | 16 → 8 | 1~3개 층, 각 너비 4~128 |
| 활성화 | ReLU | ReLU / Tanh |
| 드롭아웃 | 0 | 0~0.5 |
| 가중치 감쇠 | 0 | 0~0.1 |
| 검증 비율 | 20% | 10~40%, 각 출처의 시간순 뒤쪽 행 |
| 조기 종료 대기 | 30 | 0~100회, 0은 끄기 |
| 분류 임계값 | 0.5 | 0.1~0.9, 이 확률 이상을 사용 중으로 판별 |
| 랜덤 시드 | 42 | 0~2147483647 |
| 입력 표준화 | 사용 | 학습 구간의 평균·표준편차만 적용 |
| 클래스 균형 보정 | 끄기 | 학습 구간의 클래스 비율로 BCE 양성 가중치 계산 |
| 조도 제외 비교 | 켜기 | 가능할 때 같은 설정의 비교 모델 추가 |
| 완료 모델을 기본 예측에 사용 | 끄기 | 끄면 기본 모델 유지, 새 버전만 기록 |

실행 한도는 CPU 개발 환경 기준입니다. 작은 배치·큰 신경망·많은 에포크는 오래 걸릴 수 있습니다. 검증 손실이 가장 낮은 가중치를 선택하며, 조기 종료를 꺼도 마지막 가중치를 무조건 선택하지 않습니다. 클래스 균형 보정은 학습 손실에만 적용하고 검증 손실은 원본 분포의 BCE로 측정합니다.

## 모델 버전과 저장 구조

**버전은 학습된 모델과 그 설정을 뜻합니다.** 웹에서 명시적으로 학습하여 성공할 때마다 다음 `vN`을 등록합니다. 동일한 설정과 가중치로 재현된 실험도 새 학습 이력으로 보존하며, 같은 가중치인지 식별값으로 표시합니다. 화면·폴더 변경이나 Compose 재실행만으로 버전을 만들지 않습니다.

기존 v1~v3 가중치를 덮어쓰지 않습니다. `models/weights/current.json`은 기본 모델을 가리킵니다. 학습 완료 시 기본 적용을 켜거나 대시보드의 **기본 모델로 사용** 버튼을 누르면 다른 팀원의 버전 없는 예측 요청에도 해당 모델이 적용됩니다. 화면에서 실험 버전만 선택하면 해당 브라우저의 실험 대상만 바뀝니다.

정확도가 85% 미만인 피처 실험도 저장하고 기준 미달로 표시합니다. 피처의 영향을 비교하기 위한 학습을 정확도 기준으로 차단하지 않습니다. 최초 기본 모델을 준비할 때만 기존 85% 정확도 기준을 적용합니다.

```text
scripts/check_frontend.mjs       JSX 정적 렌더링·평가 그룹 표시 검사
scripts/runtime_logging.py       실행별 API·추론·학습 JSONL 기록
logs/<기동시각Z-실행ID>/           api.jsonl / model.jsonl, Git 제외
state/classrooms.sqlite3         강의실 최신 상태·짧은 이력·공유 시계, Git 제외
compose.yaml / .env.example      루트 실행·환경 변수 예제
```

`models`에는 모델 코드와 가중치만 두며 보고서는 루트 `reports`에 둡니다. 기존 모델은 당시에 저장된 학습 정보만 표시합니다. 없는 하이퍼파라미터나 손실 곡선을 추정해서 채우지 않습니다. 가중치와 버전별 학습 보고서는 팀원이 공유할 수 있도록 Git에서 제외하지 않습니다.

API는 모델·스크립트 코드와 원본 데이터를 읽기 전용으로 마운트하며, 가중치·보고서·로그 경로에만 결과를 씁니다. 개발 환경에서 바인드 마운트의 파일 권한 차이를 줄이기 위해 trainer와 API는 컨테이너 root로 실행합니다. 애플리케이션 루트 파일시스템은 읽기 전용이고 임시 파일은 `/tmp`를 사용합니다. 프런트는 프로덕션 빌드하지 않습니다.

## 예측 입력

| 필드 | 의미 | API 범위 |
|---|---|---|
| `Temperature` | 기온, °C | -50~60 |
| `Humidity` | 상대습도, % | 0~100 |
| `Light` | 조도, lux | 0~1,000,000 |
| `CO2` | CO₂, ppm | 0 초과~1,000,000 |
| `Hour` | 측정 시간, 시 | 정수 0~23 |
| `DayOfWeek` | 측정 요일 | 정수 0~6, 월 0~일 6 |

예: 수요일 오후 2시는 `Hour: 14`, `DayOfWeek: 2`입니다. 학습 CSV의 `date`에서도 같은 기준으로 추출합니다. 시간은 24시간 주기의 sin/cos, 요일은 7일 주기의 sin/cos와 주말 여부로 변환하며 학습·추론이 같은 함수를 사용합니다. 선택에서 제외한 피처는 실제 신경망 입력에 들어가지 않습니다. 예측 API는 모든 버전에서 같은 6개 필드를 받고 모델의 피처 목록에 없는 값은 무시합니다.

```cmd
curl http://localhost:8000/compare --json @backend/examples/mock_sensor.json
curl http://localhost:8000/compare?version=v3 --json @backend/examples/mock_sensor.json
```

응답의 `with_light`는 기존 API 호환을 유지하는 **선택 모델** 키입니다. 새 실험에서는 해당 모델도 조도를 포함하지 않을 수 있으므로 `/metrics`의 `features`를 확인합니다. `without_light`는 비교 모델을 저장한 버전에만 반환합니다. `/predict`는 선택 모델 하나의 `model_version`, `occupancy`, `label`, `probability`를 반환합니다. `mode=without_light`로 비교 모델을 직접 요청할 수 있습니다.

누락·추가 필드, 문자열 숫자, 참/거짓 숫자, 범위 오류, NaN·무한대는 HTTP 400, 없는 버전·작업·비교 모델은 HTTP 404입니다. 외부 예측 API는 위 물리 범위를 유지합니다.

웹 센서 실험과 미리보기는 **선택 모델이 실제 fit에 사용한 행의 관측 범위**로 제한합니다. 새 학습은 float32 변환 전 센서 최솟값·최댓값과 시간·요일 관측값을 체크포인트·보고서의 `input_limits`에 저장하므로 이후 CSV를 갱신해도 유지됩니다. 검증·평가 행은 범위 계산에 쓰지 않습니다. 기존 버전은 저장 당시 CSV 해시와 연속 학습 구간을 검증하여 복원하며, 검증할 수 없으면 입력을 차단하고 사유를 표시합니다. `/versions/{version}/training`에서 모델별 범위를 확인합니다.

범위 밖 예제는 이유와 함께 비활성화하고, 버전 전환 후 기존 입력이 범위 밖이면 수정 전까지 예측을 막습니다. 범위를 확인할 수 없는 버전도 예측을 비활성화합니다. 선택 모델이 사용하지 않는 필드는 API 계약을 맞추기 위한 유효한 기본값으로 보내며 해당 모델의 예측에 사용하지 않습니다. 모델 모드를 바꾸면 다시 예측해야 합니다. 관측 범위 안이라는 사실이 정확도를 보장하지는 않습니다.

## API

| API | 용도 |
|---|---|
| `GET /health` | 기본 모델 준비 상태 |
| `GET /versions` | 버전별 피처·설정·평가·가중치 상태 |
| `GET /versions/{version}/training` | 전체 학습 보고서, 기존 버전은 저장된 정보 |
| `POST /versions/{version}/activate` | 기본 예측 모델 적용 |
| `GET /metrics?version=v3` | 선택 모델 평가 |
| `GET /comparison?version=v3` | 저장된 모델들의 비교 평가 |
| `POST /predict?version=v3&mode=primary` | 모델 하나로 예측 |
| `POST /compare?version=v3` | 저장된 모델들로 같은 입력 예측 |
| `GET /training/options` | 기본 학습 설정·입력 한도·데이터 분포 |
| `POST /training/jobs` | 설정 JSON으로 학습 시작, HTTP 202 |
| `GET /training/jobs` | 학습 요청 이력 |
| `GET /training/jobs/{id}` | 진행률·곡선·상태·완료 버전 |
| `POST /training/jobs/{id}/cancel` | 학습 중지 요청 |

학습 설정 예시는 Swagger의 `TrainingConfig`에서 확인합니다. `{}`를 보내면 기본 설정으로 새 모델을 학습합니다. 허용 필드 밖의 값은 거부합니다. 모델 등록은 성공한 학습 프로세스가 선택 모델과 가능한 비교 모델의 가중치·보고서를 완성한 뒤 수행하며, 기본 모델 정보는 마지막에 원자적으로 교체합니다.

## 데이터와 성능 해석

- 학습 파일 32,387건, 별도 평가 파일 18,479건입니다. 검증 비율은 학습 CSV 내부의 기존 자료·Room A·Room B 각각을 시간순 fit/validation으로 나눕니다. 출처는 신경망 입력에 추가하지 않습니다.
- 기존 학습 8,143건과 평가 12,417건의 행·역할을 유지하고 새 자료 30,306건을 추가했습니다.
- 새 자료는 두 방을 합쳐 시간순 앞 80%인 24,244건을 학습에, 뒤 6,062건을 평가에 배치했습니다. 경계의 같은 시각은 모두 평가 쪽에 둡니다.
- 같은 출처의 동일 시각 그룹을 fit/validation 경계 양쪽에 나누지 않습니다. 출처가 다른 행끼리는 시각이 겹칠 수 있습니다. 평가 파일은 fit/validation에 포함하지 않으며 같은 출처·시각이나 동일 기록이 학습·평가 파일에 겹치면 학습을 거부합니다.
- 웹에서 검증 비율을 바꾸면 실제 출처별 fit/validation/test 행수와 클래스 분포를 표시합니다. 빈 분할·전체 클래스 부재 등 학습 불가능한 설정은 시작 전에 차단합니다. 단일 클래스 출처 부분집합은 경고하고 ROC-AUC·평균 정밀도를 `null`로 기록합니다.
- 완료 보고서에는 전체 지표와 출처별 행수·클래스 분포·정밀도·재현율·F1·혼동 행렬을 기록합니다. 대시보드의 최고값·차트는 평가 CSV SHA-256와 행수가 같은 버전끼리만 비교합니다.
- 기존 v3의 당시 평가 12,417건 지표는 조도 포함 98.96%, 제외 85.17%입니다. 갱신된 18,479건 평가 자료나 변경된 설정의 성능을 이 값으로 보장하지 않습니다.
- 정확도뿐 아니라 정밀도·재현율·F1·혼동 행렬·학습 기간 이후 지표도 확인합니다. 예컨대 모두 비어 있음으로만 예측해도 데이터 분포 때문에 높은 정확도가 나올 수 있습니다.
- 평가 정답으로 가중치나 임계값을 자동 선택하지 않습니다. 같은 평가 파일을 보며 반복 실험하는 동안 평가에 적응할 수 있으므로 최종 성능은 새 데이터로 검증해야 합니다.

이 모델은 현재 재실 판별이며 미래 예약·미래 사용 여부를 예측하지 않습니다.

추가 데이터 반영은 모델 학습과 별개입니다. `scripts/merge_data.py`를 Python으로 실행하면 `intermi/Room_A`, `Room_B`의 `df_features.csv`와 `df_occ.csv`를 시각으로 연결하고 공통 센서 4개만 추출하여 기존 CSV를 갱신합니다. 이미지 정답의 0명은 비어 있음, 1명 이상은 사용 중으로 변환하며 UTC 시각을 유지합니다. 유효하지 않은 센서·정답은 제외 건수로 표시하고 재실행은 중복을 추가하지 않습니다. 원시 데이터와 ZIP은 읽지 않으며, 학습은 웹에서 별도로 시작합니다.

`data/dataset_sources.json`은 CSV 행 순서에 맞춘 출처와 CSV SHA-256을 보존합니다. 같은 시각의 두 방은 전체 센서·정답과 발생 순번으로 연결합니다. CSV와 출처 파일은 함께 공유하며, 불일치하면 학습을 차단합니다. 기존 CSV만 있고 출처 메타데이터가 없는 단일 출처 자료는 `legacy`로 취급합니다.

이 세 데이터 파일은 `.gitattributes`로 Git의 줄바꿈 자동 변환을 끕니다. Windows와 Linux에서 체크아웃한 바이트·SHA-256이 같아야 출처 검증을 통과할 수 있습니다.


## 실행별 로그

API worker의 초기화 시각(`backend.app` 로드 시각)을 기동 기준으로 사용합니다. API 시작 시 자동으로 `logs/20261028T120000_000000Z-<실행ID>/` 같은 폴더를 만들고, `Z`는 UTC를 뜻합니다. 재시작·개발 reload는 새 실행 ID를 사용하며 과거 로그를 덮어쓰거나 자동 삭제하지 않습니다. 기존 기본 모델을 사용하는 런타임 trainer는 추가 학습을 하지 않습니다. 기본 모델이 없어 직접 초기 학습을 수행하는 경로는 별도 실행 ID를 사용합니다.

- `api.jsonl`: 서버 시작·종료, 요청 ID, UTC 시각, HTTP method·경로·라우트, 상태 코드·처리시간, 오류 유형·검증 오류 필드입니다. healthcheck도 기록하며 Authorization·Cookie·쿼리 문자열·요청/응답 본문 전체를 덤프하지 않습니다.
- `model.jsonl`: `event_type=inference`는 검증된 실제 센서 입력, 버전·모드·피처·임계값·가중치 쌍 fingerprint와 예측 결과를 기록합니다. `/compare`도 각 모델 결과를 같은 request ID에 연결하고 결과마다 inference ID를 부여합니다.
- `event_type=training`은 향후 학습 실행 때 작업 ID, 설정·시드, 실제 데이터 해시·출처별 분할, 에포크 손실, 완료 버전·평가 결과, 중지·실패를 기록합니다. 배치마다 대형 로그를 남기지 않으며 작업 상태와 실행 stdout/stderr는 기존 `reports/jobs`에도 유지합니다.

자식 학습 프로세스에는 부모 API의 실행 ID·로그 경로·요청 ID를 전달합니다. API가 재기동되어도 이미 시작한 작업은 원래 실행 폴더에 계속 기록합니다. 로그 행은 `schema_version=1` 및 run/request/job/inference 식별값으로 연결하며, 프로세스 간 파일 잠금과 매 기록 후 flush를 적용합니다. 기록 실패는 stderr에 표시하고 정상 예측이나 학습 결과 저장을 막지 않습니다. `logs/`는 쓰기 가능한 별도 Docker bind mount이고 코드·Compose가 필요한 폴더를 생성합니다.

**예측 결과는 정답이나 강화학습 보상이 아닙니다.** 현재 실제 정답·행동·보상 수집은 없으며 로그에 이를 추정해 넣지 않습니다. 이 로그만으로 강화학습 데이터가 완성되지는 않습니다. 이후 실제 관측·정답·보상을 식별값으로 연결해야 합니다.

API 로그와 모델 로그는 운영 추적뿐 아니라 **학습 설정·데이터·버전·사용 피처·센서 입력·예측 결과를 연결하여 향후 재학습과 강화학습용 데이터 구성을 위한 기반**으로 남깁니다. 강의실 측정은 classroom/measurement/inference/session 식별값을 추가하며 시연 합성 자료를 실제 관측 정답으로 취급하지 않습니다.
